# Story 1.7: CLI `dustin plan` and committed fixture plan output

Status: in-progress

## Story

As a reviewer,
I want to run `dustin plan <account> --to <destination>` and read the plan, or read the committed plan for the fixture,
so that I can verify Deliverable 1 without writing code.

## Acceptance Criteria

1. Given the fixture, when `dustin plan <fixture> --to <destination>` runs, then the plan is printed in plain ASCII (at most 120 columns): the header (network, ledger, account with balance and spendable XLM, destination, sponsor and fee bid, status), every step in execution order with its transaction and reason, the transactions with operation counts and fee bids, the recovery summary (XLM to the destination, reserves returned to sponsors, 0 paid by the account), the sequence guard, blockers, unclosable items and warnings when present, and the next command; the exit code is 0 (canonical decision 5: a printed plan is 0 even when it is partial or blocked).
2. Given `--json`, then exactly the `ClosePlan` JSON is written to stdout and nothing else.
3. `dustin close` without `--execute` prints the same plan followed by "Next: add --execute to run this plan"; it never reads a secret.
4. Given no destination, a malformed or C address, or a network other than testnet, then the CLI exits 2 with the error code and a remedy; given an unreachable Horizon, it exits 6.
5. `evidence/plan/` holds the fixture's plan as text and JSON with the command line and the capture time at the top, regenerated by `npm run evidence:plan -- <manifest>`.
6. `renderPlan()` is exported by the SDK.

## Tasks / Subtasks
