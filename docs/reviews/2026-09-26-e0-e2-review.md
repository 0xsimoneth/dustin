## Verified as conforming

Package `stellar-dustin` with bin `dustin`; Horizon only; every close transaction is a fee bump with the sponsor signing only the outer envelope and the inner fee `"0"`; bid = max(last ledger base fee, `fee_charged.p80`) floored at 100 and capped, budget 5 XLM; BigInt stroops throughout (the only `Number()` uses are ledger arithmetic, time bounds and CLI parsing); `changeTrust` limit is the string `"0"`; `close` without `--execute` behaves as `plan`; `--partial` and `--prefer-destination` with the SOW order as default; exit codes 0, 1, 2, 3 and 6 wired (4 and 5 pending E2-S3); the planner cannot sign (ESLint boundary, type-level test, GET-only test); sequence guard `seq + txIndex + 1 < (ledger + 1) << 32` with `unblocksAtLedger = (seq >> 32) + 1`; merge separated with a preflight when market steps exist; grouping per decision 6; testnet guard on every entry (passphrase plus a GET of Horizon root in the fixture path); sponsored trustlines removed by the owner alone with the reserve attributed to the reserve sponsor; blockers include claimable balances the account created; the raised-threshold fix has a regression test; the property test runs 600 seeds and asserts branch coverage; the offline tier stubs `fetch`; the testnet tier is gated. Protocol checks for the pool-share change were confirmed against developers.stellar.org (two base reserves per pool-share trustline, `CHANGE_TRUST_CANNOT_DELETE` semantics, derived authorization, lexicographic asset order).

Security: no seed, token or key in the tree or in any historic diff; `.env` ignored, `.env.example` placeholders only; `keys.json` written with mode 0600; `DustinError` redacts on construction; argv seed guard; mainnet refused at four layers; destination self, missing, contract and memo-required cases refused; lockfile v3 with integrity, actions SHA-pinned, `permissions: contents: read`, testnet workflow `workflow_dispatch` only; `npm audit --omit=dev` clean (one dev-only low in esbuild via tsup).
