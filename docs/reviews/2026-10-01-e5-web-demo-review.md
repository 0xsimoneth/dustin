## Parity

The page's plan for the recorded fixture (`test/fixtures/horizon/messy`) and `node dist/cli/main.js plan <account> --to <destination> --sponsor <sponsor> --json`, run against a local server that replays the same fixtures, give the same `planHash`, `25be835c88e84af36e96e17fa00fcbf465f6f39a7c6075deab940106eff38c85` (the value `test/unit/canonical-json.test.ts` pins), and the same document but for `network.horizon`, which records the Horizon each one asked and is outside the hash. The test is `web/test/parity.test.ts`; it needs the root build, as the page does.

## Content-Security-Policy

`default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self' https://horizon-testnet.stellar.org; object-src 'none'; base-uri 'none'; form-action 'self'`, as a meta tag in `web/index.html`. The built page keeps it as written: its stylesheet is a `<link>`, and `dist/index.html` has no inline `<style>` or `<script>` (checked on the build of this pass). The dev server injects CSS as inline `<style>` elements, which the policy refuses, so a plugin in `web/vite.config.ts` adds `'unsafe-inline'` to `style-src` for `vite dev` alone (probed by hand: the page styled, no violation in the console); `vite preview`, which the Playwright run uses, serves the strict policy. The Playwright run asserts the tag and collects every console message that names the policy: none in 18 runs. `frame-ancestors` is not in the tag because a meta tag cannot carry it.
